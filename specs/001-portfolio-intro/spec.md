### 使用者故事 1 - 個人資料卡顯示 (優先級: P1)

為訪客展示個人的基本介紹資訊，包括姓名、職稱、專業領域簡介、頭像等，提供第一印象
。

**優先級原因**: 這是個人介紹頁最核心的功能，訪客首次進頁面時需要立即看到個人的基
本身份資訊。此功能構成頁面的主要價值。

**獨立測試**: 能夠正確顯示個人資料卡，包含所有基本信息。可以獨立於其他功能進行測
試和展示。

**接受場景**:

1. **給定** 訪客初次訪問個人介紹頁，**當** 頁面加載完成，**那麼** 個人資料卡應在
   上方突出位置顯示，包含姓名、職稱、簡介、頭像，下方提供 LinkedIn 和 GitHub 圖
   示連結
2. **給定** 查看個人資料卡，**當** 點擊 LinkedIn 或 GitHub 圖示，**那麼** 應在新
   視窗中打開對應的社交媒體頁面
3. **給定** 訪客查看個人資料卡，**當** 點擊 CV 下載按鈕，**那麼** 應開始下載個人
   CV PDF 檔案
4. **給定** 訪客在不同設備上訪問，**當** 頁面加載，**那麼** 個人資料卡應響應式調
   整，手機/平板/桌機都能正確顯示社交連結和 CV 下載功能

---

### 使用者故事 2 - 作品集展示區 (優先級: P1)

展示個人完成的精選項目、作品或案例研究，以向潛在雇主或合作者快速展示能力代表作。

**優先級原因**: 作品集是個人介紹頁的核心價值提案，訪客進頁面的主要目的就是查看你
的代表作品。缺少此功能則介紹頁失去重要價值。

**獨立測試**: 能夠正確顯示精選作品列表，並可以點擊查看詳情或訪問完整作品集。此功
能不依賴其他故事但可以進一步增強。

**接受場景**:

1. **給定** 訪客在個人介紹頁，**當** 向下滾動到作品集區域，**那麼** 應以網格或列
   表形式顯示 3-5 個精選項目，每個項目顯示標題和預覽圖片
2. **給定** 查看精選作品列表，**當** 點擊某個項目卡片，**那麼** 應顯示項目詳細資
   訊（描述、使用技術、相關連結等）或跳轉至對應的項目頁面/外部連結
3. **給定** 訪客查看精選作品，**當** 想查看完整作品集，**那麼** 應提供明確的導航
   連結指向完整作品集頁面或作品檔案庫

---

### 使用者故事 3 - 技能與專業標籤展示 (優先級: P2)

清楚展示個人掌握的技能、技術棧和專業領域，幫助訪客快速了解專業能力。

**優先級原因**: 這能進一步增強訪客對個人專業度的理解，但不如基本介紹和作品集關鍵
。可作為 MVP 完成後的增強功能。

**獨立測試**: 能夠正確渲染技能標籤，並支持分類顯示。

**接受場景**:

1. **給定** 訪客查看個人介紹頁，**當** 滾動到技能區域，**那麼** 應以標籤或分類方
   式展示至少 10-15 項技能，按類別分組（如前端、後端、工具等）
2. **給定** 技能列表顯示中，**當** 內容超過可視區域，**那麼** 應支持平滑滾動或視
   覺上易於掃描的分類顯示
3. **給定** 訪客在不同網絡條件下訪問，**當** 頁面加載，**那麼** 技能標籤應快速渲
   染，不阻塞頁面交互

## 需求 _(必填)_

### 功能性需求

- **FR-001**: 系統必須顯示個人的基本資料卡，包含姓名、職稱、專業領域簡介和頭像，
  並在下方提供社交連結（LinkedIn + GitHub 圖示連結，點擊另開視窗）和個人 CV PDF
  下載功能
- **FR-002**: 系統必須展示作品集項目列表，每個項目需包含標題、簡介、技術標籤、預
  覽圖片和外部連結
- **FR-003**: 系統必須展示技能與專業標籤，支持按類別（如前端、後端、工具等）分組
  顯示
- **FR-004**: 系統必須提供清晰的頁面導航，在固定導航欄或頁面頂部提供錨點，讓訪客
  能快速跳轉到個人簡介、精選作品、技能標籤等主要區域
- **FR-005**: 系統必須支持響應式設計，在手機、平板和桌機上都能正確顯示（相符於
  Constitution 中的 UX 一致性原則）
- **FR-006**: 系統必須優化圖片加載和顯示，包括圖片懶加載、現代格式支持 (WebP)，
  以及加載失敗時的備用內容
- **FR-007**: 系統必須符合無障礙標準，提供適當的語意 HTML 和 ARIA 標籤（相符於
  Constitution 中的 WCAG 2.1 AA 要求）
- **FR-008**: 系統必須以繁體中文為主要語言版本，英文為補充版本，可逐步實現部分內
  容的英文化，為國際訪客提供基本可讀性

### 關鍵實體 _(涉及數據)_

- **個人資料 (PersonalProfile)**: 表示個人的基本身份信息，包括姓名、職稱、簡介、
  頭像 URL、LinkedIn URL、GitHub URL，以及個人 CV PDF 文件的儲存位置
- **作品項目 (PortfolioItem)**: 代表一個完成的項目或案例，包含標題、描述、使用技
  術標籤、預覽圖片、相關連結、完成日期等
- **技能標籤 (Skill)**: 代表掌握的技能，包括技能名稱、類別、熟練度等級（可選），
  以及相關項目關聯（可選）

## 澄清記錄

### Session 2025-12-21

**澄清 1**: 確認此為純靜態展示頁面，不需要編輯/登入功能

- **Q**: 系統如何確認有編輯權限的人身份？
- **A**: 不需要登入功能 - 此為純靜態展示頁面
- **影響**: 移除 FR-004 (編輯功能)、移除 UserAccount 實體、調整使用者故事以移除
  編輯相關場景

**澄清 2**: 作品集項目展示策略

- **Q**: 個人介紹頁初始要展示多少個作品項目？是否有「重點精選」和「全部作品」的
  區分？
- **A**: A - 首頁展示 3-5 個精選項目，提供連結到完整作品集頁面
- **影響**: 使用者故事 2 改為展示精選項目，並提供導航連結到完整作品集

**澄清 3**: 多語言支持範圍

- **Q**: 多語言支持的實現方式和範圍是什麼？
- **A**: A - 繁體中文為主要版本，英文為補充版本（可部分內容英文化）
- **影響**: 調整 FR-008 以反映漸進式多語言支持策略，優先完成繁體中文版本

**澄清 4**: 聯繫方式與互動功能

- **Q**: 個人資料卡中應該包含哪些聯繫方式？
- **A**: 不提供 Email，僅提供 LinkedIn + GitHub 社交媒體連結，額外提供個人 CV
  PDF 下載功能，所有連結以 icon + link 形式，點擊後另開視窗
- **影響**: 更新 FR-001 和相關接受場景，具體化聯繫方式的呈現方式和組成

**澄清 5**: 頁面內容與導航架構

- **Q**: 個人介紹頁面的主要區域構成是什麼？
- **A**: A - 標準結構：個人簡介 → 精選作品 → 技能標籤 → 頁尾
- **影響**: 確認頁面架構清晰，簡化導航需求，聚焦三個核心區域
